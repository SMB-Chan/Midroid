# Midroid

[![Android CI](https://github.com/SMB-Chan/Midroid/actions/workflows/android.yml/badge.svg)](https://github.com/SMB-Chan/Midroid/actions/workflows/android.yml)
[![License](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](LICENSE)

Midroid is an **experimental, unofficial Android client for Misskey** designed to reduce unnecessary foreground rendering and background work compared with using a generic browser/PWA configuration.

Midroid is an independent community project and is not affiliated with or endorsed by the Misskey project or individual Misskey instance operators.

The current architecture deliberately **does not fork Chromium**. It uses Android System WebView (Chromium-based) as the rendering engine and adds a small native control layer around lifecycle suspension, renderer priority, navigation boundaries, power modes and selected Misskey-specific usability controls.

> **Preview status:** Midroid is still under active development. Use the public release APKs only if you are comfortable testing pre-stable software. Keep Android System WebView up to date.

## Install

Public builds are distributed through **GitHub Releases**.

For normal use:

1. Open this repository's **Releases** page.
2. Download `Midroid-X.Y.Z.apk` from the latest appropriate release.
3. Download the matching `Midroid-X.Y.Z.apk.sha256` file.
4. Verify the APK SHA-256 before installing when possible.
5. Allow your Android file manager/browser to install that APK if Android asks for permission.

The Release also includes `Midroid-X.Y.Z.signing.txt`, generated by `apksigner --print-certs`, so the signing certificate can be compared between releases.

**Do not use `Midroid-ci-debug-apk` Actions artifacts as the normal update channel.** Debug builds use a developer/debug signing identity. Public Releases are built only with the dedicated persistent Midroid release key so Android can accept future releases as in-place updates.

Historical test/debug installations may need to be uninstalled once before the first stable-signed Midroid APK can be installed. That one-time uninstall clears Android app data and WebView login state. Later APKs signed with the same release key should update in place.

## Requirements

- Android 8.0 / API 26 or later
- A reasonably current Android System WebView provider
- An HTTPS Misskey instance

The project currently compiles and targets Android SDK 36.

## Current features

- Native Kotlin Android app using Android System WebView as the rendering engine.
- Connect to an arbitrary HTTPS Misskey instance.
- Preserve WebView cookies/login state.
- Keep same-origin Misskey top-level navigation inside Midroid.
- Route non-instance top-level links to the system browser/app.
- Eco / Balanced / Performance power modes.
- Visibility-aware WebView suspension and renderer-priority control.
- Renderer recovery through `onRenderProcessGone`.
- Eco reduced-motion and autoplay suppression.
- Refresh-rate scheduling hints where supported by the Android version.
- Density/screen-aware WebView text scaling.
- Configurable Misskey reaction scaling.
- Multi-account/profile support where the installed WebView provider supports WebView multi-profile APIs.
- Storage-aware WebView cache tuning on supported versions.
- Interruptible media loading and Misskey lightbox-aware Back handling.
- File picker support for Misskey attachments.
- Authenticated HTTPS downloads through Android DownloadManager.
- Native audio fallback for supported Misskey media.
- System-bar, display-cutout and keyboard inset handling so native/WebView controls stay reachable.
- Cleartext traffic disabled; SSL errors are never bypassed.
- WebView remote inspection enabled only in debuggable builds.
- Privacy-safe `MidroidDiag` lifecycle/renderer diagnostics.
- Reproducible ADB capture tooling for Chrome/PWA vs Midroid comparisons.
- Persistent release-signing path for update-compatible APKs.

## Known limitations

Midroid is not a full browser and intentionally keeps a narrow security/maintenance surface.

Current limitations include:

- no native Web Push bridge yet;
- no direct ownership of Misskey's internal WebSocket objects;
- WebRTC camera/microphone permission is currently denied by the Midroid client;
- compatibility can vary with Android System WebView and Misskey versions/configuration;
- some behavior remains dependent on the configured Misskey instance and resources that instance loads.

## Privacy and security

Midroid does not include an analytics or advertising SDK and does not operate a Midroid telemetry backend. Web content is loaded directly through Android System WebView from the user-selected Misskey instance and resources requested by that page.

Diagnostics are designed to exclude URL paths, query strings, fragments, note IDs, cookies and authentication tokens. Review copied diagnostic text before posting it publicly.

See:

- `PRIVACY.md` for the project privacy notice;
- `SECURITY.md` for vulnerability reporting;
- `docs/UPDATES.md` for signing/update details.

Potential security vulnerabilities should **not** be reported in a public issue before a fix/disclosure plan exists.

## Build from source

Requirements:

- JDK 17+
- Android SDK 36
- Android Studio Quail 4 (2026.1.4) or a compatible newer version, or Gradle 9.6.0

A checked-in Gradle wrapper is not yet part of the project. Use Android Studio's configured Gradle or Gradle 9.6.0.

Run the core verification used by CI:

```text
gradle lint testDebugUnitTest assembleDebug assembleRelease
```

Without the release-signing environment variables, `assembleRelease` is suitable for compile/R8 verification but is **not** an official Midroid update APK.

GitHub Actions always uploads a `Midroid-ci-debug-apk` developer artifact. Ordinary CI deliberately does **not** produce an update-compatible APK; persistent release signing is reserved for the tag-driven public release workflow.

## Public release process

Public Releases are intentionally stricter than ordinary CI.

A tag matching `vMAJOR.MINOR.PATCH` (pre-release suffixes are also supported) triggers `.github/workflows/release.yml`. The workflow:

1. requires all four persistent signing secrets;
2. runs lint and JVM tests;
3. builds the non-debuggable, minified release APK;
4. verifies the APK signature;
5. verifies that the Android `versionCode` increases and generates SHA-256, certificate-report and version-code assets;
6. creates the GitHub Release and attaches those assets.

If stable signing is not configured, the release workflow fails instead of publishing an unsigned or debug-signed package.

Maintainers should follow `docs/RELEASING.md` before creating a public tag.

## Measure before forking Chromium

Midroid includes a raw-data ADB benchmark collector:

```text
bash tools/benchmark_android.sh dev.midroid.app 600 midroid-balanced-01
```

For a repeatable background-residence test:

```text
MIDROID_SCENARIO=background MIDROID_WARMUP_SECONDS=10 \
  bash tools/benchmark_android.sh dev.midroid.app 1200 midroid-balanced-background-01
```

Use the same collector with Chrome or the installed WebAPK package to build an A/B dataset. The collector records battery, CPU, process, memory, frame timing, network and lifecycle/WebView evidence instead of reducing the experiment to one opaque score.

See `docs/BENCHMARKING.md` for the controlled A/B/A protocol.

## Why WebView first?

Forking Chromium immediately would make Midroid responsible for fast-moving browser security updates and a large native build surface before measurements show which browser-level changes are actually necessary. The WebView stage is intended to identify bottlenecks experimentally. If profiling finds a bottleneck that WebView APIs cannot control, that evidence can define the smallest justified Chromium patch set.

Native notifications are intentionally a separate subsystem. The compatibility target is standards-compatible push behavior rather than keeping a permanent background WebSocket solely for notifications. See `docs/NOTIFICATIONS.md`.
