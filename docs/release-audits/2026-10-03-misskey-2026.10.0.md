# Misskey 2026.10.0 compatibility note

Source review for Misskey 2026.10.0 against the Midroid client. This is not a
device-matrix record and does not replace `v0.2.0.md`. Device checks were not run.

## Client DOM hooks

Unchanged. Midroid still binds:

- `.omfetrab` (notification / reaction tuning in `MisskeyUiTuner`)
- `._modalBg` (lightbox detection in `MisskeyMediaFallbackBridge`)
- `#pswp` (native audio fallback scope and back-navigation lightbox state)

No injection-script update is required for this Misskey release.

## Server behavior Midroid already speaks

- `i/revoke-token` still works. Account removal keeps the Misskey 2026.9.0+ body (`i` and `token` are the same access token) and the 401 / 404 classification.
- `sw/unregister` on 2026.10.0 requires `endpoint`, `auth`, and `publickey`. Ownership is those subscription keys; `i` scopes a user delete when a token is still valid. Midroid always sends the keys (the same `auth` / `publickey` values as `sw/register`) and still sends `i` when it has a token. 2026.9.x ignores the unknown key fields.
- `sw/register` endpoint checks match `PushNotificationService.isValidEndpoint`: HTTPS only, and URL userinfo is rejected. Midroid enforces that in `RelayProtocol.parseEndpointId` before building a register body.

## Misskey fixes with no Midroid change

- `MkModal` null guard, `MkCustomEmoji` inject default, and user-home pull-to-refresh are client-side Misskey fixes. They do not affect Midroid's injection scripts.
- `stream/Connection.ts` serialization is server-side. No client change.
- Attachment delivery always sends `Accept-Ranges` and `Content-Length`, with cleaned-up Range handling. The native audio fallback is unaffected.

## Not run

- No emulator and no physical device. Renderer priority, the 30-second background grace, settings reuse, and the connecting overlay were not exercised on a device.
